# 森ステージのSkybox軽量化試作

## 開き方

`Assets/Scenes/ForestStage_Skybox.unity` を開いてPlay。
原版は `Assets/Scenes/ForestStage_Realistic.unity`。原版のシーン・TerrainData・木の素材は変更していない。
Build Settingsのシーン選択は原版のまま。軽量版の配布ビルドを作る場合は、対象シーンを軽量版へ切り替える。

## 変更内容

- Terrainの木620本のうち354本を既存素材から撮影したSkyboxに置換。3Dの木は266本。
- 対象はワールドZ < 120で、|X| > 30またはZ < -34の外周部分。湖畔の近い木、特徴的な古木、コース、当たり判定、毒沼側の木の配置は保持。
- Z = -12 / 35 / 80 / 125、Y = 5から地面も含めて撮影した2048×1024のパノラマ4枚を使用。カメラのZに応じて隣り合う2枚をSmoothStepで補間する。後戻りにも対応し、範囲外では端の画像を使用。
- 木の形状は保持し、使用メッシュを独立したアセットへ抽出。マテリアルとテクスチャは軽量版用に複製。色は最大1024、NormalMapとしてインポートされていた法線は最大512。元のインポート種別は維持。
- 元の木と素材を共有していたシーン内の3つのRendererにも軽量版マテリアルを割り当て、重複読込を抑制。
- URP LitのTerrain自動ビルボードに既存の表示不具合があるため、その機能は有効化していない。今回のクロスフェードはSkyboxの背景間で行う。

## 計測

| 指標 | 原版 | 軽量版 |
|---|---:|---:|
| Terrainの3D木 | 620 | 266 |
| 全Terrain木の三角形合計 | 29,277,433 | 12,627,826 |
| 木の素材＋背景のWindows LZ4 AssetBundle | 31,911,137 bytes | 15,219,197 bytes |
| 森シーン全体のWindows LZ4 AssetBundle | 435,532,386 bytes | 421,186,755 bytes |
| 木の素材＋背景のEditor内テクスチャメモリ | 64,154,195 bytes | 33,553,857 bytes |

三角形合計は全配置の合計であり、1フレームの描画数やFPSではない。
AssetBundleは同じ条件で作成した比較用データであり、ゲーム全体の実行ファイル容量ではない。木の素材＋背景は約52.3%減、森シーン全体は約14.35MB（約3.3%）減。地形・岩・水・キャラクターなどの残りのデータも大きいため、ステージ全体の容量削減率は木の削減率より小さい。
Editor内メモリはProfiler.GetRuntimeMemorySizeLongによる参考値で、実機のVRAM使用量とは異なる。
原版を保持しているため、リポジトリ自体の容量は試作用のアセット分だけ増える。

比較画像と機械可読の計測結果は `ScreenshotsOut/ForestSkybox/` に保存（git対象外）。

## 見た目・検証範囲

スタート・中盤・湖側で同位置のカメラから前後を撮影し、中盤の横向きも確認。Playモードでカメラ追従とクロスフェードの端点・中間点を確認。TerrainDataが独立し、高さサンプルが原版と完全一致することも確認。
Play中に出るBoxColliderの負スケール警告とピンク色の円柱は原版でも再現する既存の状態。今回のスクリプト・シェーダーにコンパイルエラーはない。
Skyboxの木は遠景画像なので、元の3Dの木より柔らかく見え、移動に伴う視差やリアルタイムの影は持たない。
本試作はコース付近からの見え方を基準にしている。外周まで移動する自由探索や大きく高度を変えるカメラには、中景や追加の撮影位置が必要。
固定カメラ3地点のFPS比較は以下に記載。全コース通しの操作テストと配布用ビルドでのFPS計測は未実施。

## FPS比較（2026-09-09）

RTX 3060 / Ryzen 5 5600、Unity 6000.5.4f1のEditor Playモードで計測。
Main Cameraの描画先を1280×720のRenderTextureに固定し、FOV 60、VSyncなし、FPS制限なし、動的解像度なし。
カメラ追従だけを一時停止し、ゲーム・物理・ポーションの処理は動作させたまま測定。Gameビューにフォーカス。
原版→軽量版→軽量版→原版の順で実施。各回の最初は15秒、地点の変更後は5秒ウォームアップしてから、各地点を約15秒計測。
計測窓内にはUnityのMCP呼び出しを行っていない。シーンや品質設定は保存せず、終了後にカメラ等の設定を復元。

| 地点 | 原版FPS | 軽量版FPS | 改善 |
|---|---:|---:|---:|
| スタート | 15.9 | 22.3 | +40.3% |
| 中盤 | 16.8 | 21.2 | +25.9% |
| 終盤 | 19.2 | 21.1 | +10.0% |
| 全サンプル集計 | 17.3 | 21.6 | +24.4% |

各地点2回分を合算し、総フレーム数÷総フレーム時間でFPSを計算（瞬間FPSの単純平均ではない）。
原版1,561フレーム／約90.06秒、軽量版1,943フレーム／約90.11秒。
平均フレーム時間は57.7→46.4ms、95パーセンタイルは138.9→118.3ms。
GPU Frame Timeカウンターの平均は28.3→18.9ms。ただしEditor全体のオーバーヘッドが含まれるため、配布用ビルドのFPSや純粋な木だけの処理時間には換算できない。
両方とも2回の計測は近い値で再現したが、停止視点の短時間比較であり、移動中のロード・クロスフェード・長時間プレイの最悪値を保証するものではない。

計測用コード: `Assets/Scripts/CarryForestFpsBenchmark.cs`（UNITY_EDITORで囲み、配布ビルドから除外。シーンには配置していない）。
各フレームの生データと集計: `ScreenshotsOut/ForestSkybox/FPS/`（git対象外）。
再測定はPlayモードで `CarryForestFpsBenchmark.StartRun("未使用のラベル")` を呼ぶ。約70秒で3地点の計測が完了する。

## 再生成

生成処理: `Assets/Editor/CarryForestSkyboxOptimizer.cs`
実行時の補間: `Assets/Scripts/ForestSkyboxBlend.cs`
シェーダー: `Assets/Shaders/ForestSkyboxBlend.shader`

原版を開き、`Carry > Optimization > Create Forest Skybox Variant` を実行する。
出力先が既に存在する場合は上書きを拒否する。再生成する場合は、比較したい既存出力を別の場所へ保管した上で、出力先を空けるかスクリプトの出力パスを変更する。
背景の焼き付けと大量変更は、このEditorスクリプトから再現可能。

新しい外部素材は導入していない。背景は既存のPoly Haven素材をUnityで描画した派生物で、元素材の記録は `ASSET_LICENSES.md` にある。
